# PWA compatibility and update policy

The built app has a standalone manifest with an explicit start URL and scope, compatible 192 px and 512 px icons, and an explicit Apple 180 px touch icon. Android and desktop installation remain browser-controlled. The app does not depend on an in-page browser install prompt. Workbox precaches the HTML shell, route chunks, styles and icons. Navigate and reload tests exercise actual service worker control with the network disabled. [Chrome install criteria](https://web.dev/articles/install-criteria), [Apple Home Screen guidance](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios)

## Updates and recovery

The app registers the production worker on a secure origin and shows offline readiness after the page has a controller. A waiting worker produces a notice. The app does not send a skip-waiting message or reload on controller change. Save edits and wait for backup or restore to finish, then close every LivestockOS window or tab on that origin before reopening. The browser activates a waiting worker after its old clients leave. Reopen online to fetch an update that has yet to download. [Service worker update lifecycle](https://web.dev/articles/service-worker-lifecycle)

Cache cleanup applies to app-shell files. IndexedDB remains at schema v4 and this release does not migrate or clear it on install or update. A confirmed restore still replaces all stores in one transaction. A restore in another tab now raises a notice without reloading the current tab. Copy any unsaved notes you need and reopen that tab before editing the restored data. If a new build does not load, reopen online on the same origin and verify your records before attempting recovery. Preserve an external backup before clearing site data.

## Backup stress reproduction

In PowerShell, set `$env:LIVESTOCK_BACKUP_STRESS='1'` and run `npm test -- --silent=false`. The opt-in Node test runs the application backup code against synthetic IndexedDB fixtures with 200 animals, 1,000 veterinary events and 42 unique 1024 × 768 PNGs. It checks a near-limit file, rejection at one byte over the ceiling, rollback after a deliberately aborted late write, two successful restores and equality after reopening. It reports file size, stage duration, process RSS, heap and process peak RSS. The Node run uses fake-indexeddb and does not measure Safari’s image decode or device memory constraints. Browser tests separately exercise actual image decode and offline IndexedDB export and restore. The physical drill remains [NOT TESTED](PHYSICAL_DEVICE_CHECKLIST.md).

One Windows Node run produced a 132,647,337 byte file (126.5 MiB). The optimized export ended at 945 MiB RSS. Preview ended at 978 MiB RSS and the process reached a peak of 1,201 MiB. A restore took roughly 0.3 seconds after preview in that run. These process measurements include the test runner and fixture data. They show why the documented file-size limit is not a mobile memory guarantee.

For supplemental desktop WebKit coverage, run `npx playwright install webkit`, set `$env:LIVESTOCK_WEBKIT='1'`, and run `npx playwright test --project=webkit --workers=1 tests/e2e/offline.spec.ts tests/e2e/backup.spec.ts tests/e2e/pwa-update.spec.ts`. The Playwright iPhone viewport uses desktop WebKit and cannot reproduce iOS Home Screen or OS file-picker behavior. On the M6 Windows host, Playwright's WebKit launcher reported missing `brotlidec.dll` and the three supplemental checks did not execute.

## M7 notification prerequisites

- Keep the current IndexedDB tasks as the in-app source of truth. On iOS/iPadOS, Web Push support starts at 16.4 for Home Screen web apps. Feature-detect the Push and Notifications APIs on installed iOS and Android Chrome. Request permission only in response to a user action and show an in-app fallback for denied, unavailable and revoked permission. [WebKit Web Push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [Chrome Push overview](https://web.dev/articles/push-notifications-overview)
- Remote push needs an approved sending component, permission and subscription lifecycle handling, VAPID keys and credential protection. A service worker would consume pushes and show notifications where supported. Sync must be explicitly approved before transmitting reminder data. Decide what minimal data may leave the device, and keep notification text generic unless the owner opts in.
- Deduplicate scheduling and delivery by stable task UUID and scheduled due date or revision. Cancel obsolete jobs after completion, cancellation, or rescheduling. Keep activation and click handling idempotent across retry and multiple devices. Test permission reset and subscription expiration.
- A service worker is not a durable local timer. A disconnected device cannot rely on receiving server pushes on time. Continue showing local reminders when LivestockOS opens. An explicitly exported calendar event could use the device’s calendar alerts after import, with an understandable procedure to manage edits and duplicates. A native wrapper with local notifications would be a separate platform decision.
